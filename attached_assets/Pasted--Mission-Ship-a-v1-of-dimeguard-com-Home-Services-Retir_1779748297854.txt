## Hard rules (apply to every file you touch)

- **Direction D palette is locked.** Brand tokens already live in `src/site.config.ts` → `brand`. Do not invent new colors or gradients. Lime `accent` (`#C8E04A`) is for buttons/highlights only — never body text on light surfaces.
- **No state-anchoring in user-facing copy.** Saral wants out-of-state visitors to feel they can still reach out. Strip "Licensed CA / TX / CO / NJ" / "licensed in four states" / "limited to" framing from every visible surface — top trust bar, hero trust strip, FAQ answers, page descriptions. The `licensure.licensedStates` data array stays in `site.config.ts` (sitemap and JSON-LD still use it); only the visible copy changes.
- **Compliance copy guardrails** (insurance-only broker, not RIA — no Form ADV gate, but still):
  - No superlatives: "best", "top-rated", "#1", "leading", "premier", "trusted by thousands".
  - No outcome-implying language: "guaranteed returns", "we'll make you wealthy", "you will save $X".
  - Use "may", "can", "designed to help", "could" — never "will" when describing outcomes.
  - No outcome-implying testimonials. If you keep a testimonial block, quotes must describe the *process* (clarity, listening, follow-up), never dollar outcomes.
  - Every page that displays planning content carries the existing `<Disclosure />` block.
- **No fabricated specifics.** Do not invent client names, dollar figures, carrier names, event dates, or testimonials. Where a real value is missing, leave a TODO comment in the source (e.g. `{/* TODO[badri]: replace with Saral's actual carriers */}`) and use a clearly-generic placeholder ("Independent — multi-carrier" vs "12 carriers").
- **Calendly URL** comes from `process.env.NEXT_PUBLIC_CALENDLY_URL`. If env var is empty, fall back to `#contact` anchor on the new /contact page — never a hardcoded Calendly link.
- **One-source-of-truth rule.** All advisor/business/NAP/brand/route metadata flows through `src/site.config.ts`. Do not hardcode the advisor name or business name in components — read from `siteConfig`.
