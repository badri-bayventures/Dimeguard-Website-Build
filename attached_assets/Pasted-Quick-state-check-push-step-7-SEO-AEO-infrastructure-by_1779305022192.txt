PART 2 — Ship step 7

After the audit, deliver these by Thursday EOD:

1. Centralized JSON-LD builders in lib/schema/, all config-driven from 
   site.config.ts so cohort reuse is one-line per advisor:
   - localBusiness(config) — name, NAP, geo, opening hours, area served 
     (Mountain House + Central Valley + the 4 licensed states), 
     sameAs (GBP URL placeholder, LinkedIn placeholder), priceRange 
     omitted (advisor doesn't disclose).
   - financialService(config) — for /retirement-planning and 
     /life-insurance, with serviceType and areaServed.
   - person(config) — Saral Toms, jobTitle "Insurance & Retirement 
     Advisor", worksFor → LocalBusiness, knowsLanguage Hindi + English.
   - faqPage(faqs) — accepts an array of {question, answer} and renders 
     FAQPage schema. Used by the <FAQ> component below.
   - article(post) — for blog posts, with headline, datePublished, 
     dateModified, author → Person, publisher → Organization, image.
   - breadcrumb(trail) — for blog and calculator routes.

2. Per-page generateMetadata across all 7 routes — title, description, 
   canonical (self-referential), OG (title, description, image, url, 
   type), Twitter (summary_large_image, title, description, image). 
   Pull defaults from site.config.ts; override per-page where needed.

3. Sitemap — app/sitemap.ts that combines static routes + Notion blog 
   slugs (pull at revalidate time, not request time). Self-referential 
   canonicals must match sitemap URLs exactly.

4. robots.txt — at app/robots.ts. Allow all, point to sitemap, no 
   blanket disallows.

5. llms.txt — at app/llms.txt/route.ts (or static if simpler). Format:
   - Site name + 1-line description
   - Canonical URLs of the 7 routes with a short summary each
   - Pointer to /sitemap.xml
   Note: this is a speculative bet — keep it cheap to maintain (driven 
   from site.config.ts route map, not hand-edited).

6. Reusable <FAQ> component that takes an array of {question, answer} 
   and emits BOTH the visible UI (semantic H3-question + answer 
   paragraph pattern, AEO-aligned) AND the FAQPage JSON-LD via the 
   faqPage(faqs) builder from #1. Replace the current home-page FAQ 
   with this component as the reference implementation.
